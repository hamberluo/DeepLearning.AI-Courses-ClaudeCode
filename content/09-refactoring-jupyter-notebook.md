# 重构 Jupyter Notebook 并制作仪表盘

Claude Code 自带读取和编辑 Jupyter notebook 的工具。这一节，我们做第二个例子：用 Claude Code **重构一个 Jupyter notebook，并把它变成一个仪表盘**。开干。

## 一个又乱又糙的 notebook

到目前为止，我们看的都是怎么用 Claude Code 处理 Web 应用的前后端。现在换个方向，展示怎么用它来对付 **Jupyter notebook**。

我这里有个 notebook，装着一些虚构的电商数据。它从 `ecommerce_data` 文件夹里的几个 CSV 读数据，用 pandas 把信息读进来、显示出来。能看到，我确实拿到了想要的答案，但**这些数据组织得并不好**：虽然有统计信息，但格式和展示都不太顺眼。

往下翻，我开始做一些更复杂的操作。比如我想从这堆数据里挖出一些洞见——像是**逐年的营收**（具体说，2023 对 2022）。该有的操作我都写了，中间还涉及两个 CSV 和数据框（DataFrame）的合并。我一步步逼近想要的答案，但过程中冒出了一些警告（warning），而且光是把想要的东西在视觉上恰当地呈现出来，就得花上不少时间。所以——结果我是拿到了，但**又啰嗦又乱**。我想要一种更好的方式来展示这些信息，也想探索怎么重构这个 notebook。

正如在另外几个部分看到的，我想算一些高层指标，比如**平均订单价值**，而且不光要这个数，还只是 2023 年的——那我要 2024 年呢，以此类推。再往下，会看到一些还不错的可视化，但我觉得能做得更好；到最底下，还在算「按州统计的销售额」这类高层数值、再画些图——我觉得用上 Claude Code 这样的工具能好很多。

带着这个想法，我们来展示怎么用 Claude Code 重构这个 notebook，把**业务逻辑**和**展示**更好地分开。

## 写一份清楚的重构提示词

我打开 Claude，准备贴进一条事先写好的提示词，它引用了这个 notebook 以及我正在用的其他文件。贴之前，我先新建一个 markdown 文件，借此说说我们到底在干什么、为什么这么干。

注意，我用 `@` 引用文件名、也用它引用文件夹名。**如果你不确定该怎么提示、怎么向 Claude 提要求，随时可以问 Claude 本身。** 我常常在用 Claude AI 或 Claude Code 时直接问它：「我想做这件事，给我一条最好的提示词来完成它。」

在我们的提示词里，有几块内容：对结构布局的**重构要求**、一些**代码质量改进**，以及对几个特定 Python 文件的要求。我们让 Claude 做的是：单独建一个 Python 文件负责**加载和处理数据**，再建一个负责**计算指标**。这种**关注点分离**，能让我们更好地测试、也更好地理解「驱动重构后 notebook 里那些可视化」的代码。我们还要求**改进可视化**，并把「改进」具体说清楚。最后，我们希望对所用数据多一点**配置**能力。

总的来说，**让 Claude 知道你期待什么，是个好习惯**。所以别只说「重构一下」，而要说：给我重构后 notebook 的底层资产、给我一种记录函数文档、计算业务指标的方式，再给我依赖相关的文件，以及一个说明怎么用的 README。

那就把这条复制、粘贴进去。你会注意到，粘贴超过一定行数后，Claude Code **不会全显示出来**，好让终端保持简洁。运行这条提示词。

和用其他工具时一样，这里会用上一套稍有不同的工具——不是普通的「读取」，而是**读取 notebook**。但那张我们已经很熟悉的待办清单照样会被执行。它用「读 notebook」的工具去探查单元格、分析结构、按预期创建出重构后的 notebook。做完后，我们应该能看到：不仅有强大的可视化，还有几个带辅助函数的文件，分别负责加载数据、处理数据、以及计算我们需要的业务指标。

接受对这些 Python 文件的改动，会看到它用对的工具把 Python 写出来。接着它再写一个带指标计算的 Python 文件，供我们最终的数据和展示用。Claude Code 处理这些任务时，我们随时能查看已创建的文件。一看就知道，这种**面向对象**的写法，比把一切都塞进 notebook 里干净多了。业务指标计算也一样——能看到它具备「传入数据框、返回可视化、并对数据做校验」的能力。看来业务指标建好了，最后是 notebook、`requirements.txt`，还有马上要写的 README。

趁它在跑，我们先看看重构后的 notebook，确保所有单元格都能如期运行。一上来视觉上就舒服多了。我看到它在试着读那条提示词，于是我跟 Claude 说一声：**不用读提示词，把 README 写完就行**。

细看这个 notebook，开箱就好太多了：有对「我在看什么数据」的分析，还有可配置项——我能指定年份、对比数据，甚至任意月份。这些常量我会贯穿整个 notebook 使用。这里能看到所需的数据加载，用到了我从那些类里来的自定义模块。

## 出了个 KeyError，让 Claude 修

我把所有单元格跑一遍，目前看起来都挺好。但再往下滚一点，会发现**这里报错了**。一眼看去，问题像是某种 **KeyError**。那我让 Claude 帮我修：我说「我跑某个单元格时遇到 KeyError」。我本可以让 Claude Code 自己去查，但我**直接把我用的代码也给它**，让它多点上下文。Claude Code 看看要怎么处理、查出问题所在、替我改好。

改完后再跑这些单元格，确认情况好转。往下滚，之前的报错没有了。再看看它返回给我的一些业务指标：摘要显示更漂亮了、客户满意度的信息也比之前更好读。转到营收分析，能看到更清晰的数值、更多展示信息，稍加打磨后，数据更容易呈现、可视化也更顺眼了。看品类表现，分析品类和相关营收的工具更好用了;看地理表现，是一张漂亮的按州可视化，鼠标悬停还能拿到逐州的更多信息。一路到底，看额外的配送分析，也都如预期般不错。

我们把这个 notebook 重构得不错：信息展示更直观，关注点也分开了。

## 从 notebook 到 Streamlit 仪表盘

但接下来我想做的，是从 notebook 迈向一个**基于网页的界面**——一个用 **Streamlit** 驱动的漂亮仪表盘。如果你不熟悉 Streamlit：它是一个 Python 库，很适合做界面、尤其是仪表盘，而且能非常顺滑地从 notebook 过渡到这些 Python 文件。

那就新建一个 markdown 文件放提示词，叫 `convert-to-dashboard.md`。我们来过一遍要写什么：让 Claude 把重构后的 notebook **按这个确切的布局**转成一个专业的 Streamlit 仪表盘。其实只写第一行也行，但为了少来回折腾，干脆把想要的都告诉 Claude——

- 一个带**标题和筛选器**的页头；
- 一排 **KPI 卡片**：营收、增长、平均订单价值、订单总数；
- 一些**图表**：营收、品类、按州营收，以及一个满意度柱状图；
- 底部一行放**两张卡片**；
- 并对数据如何展示、如何渲染给出**具体要求**。

带着这些，我们试一把：**用 Streamlit 从 notebook 迁移到可视化界面**。可以看到它创建了我们的仪表盘。跟着看它在做什么：导入 Streamlit、引入 pandas、引入包括 Plotly 在内的一些可视化库。这里能看到它写了一些自定义 CSS 做样式、设置页面配置；这些大多来自我们要用的那个 Streamlit 的 `st` 对象。它更新了 `requirements.txt`，接着要建一个展示仪表盘全貌的 README——我干脆当场告诉 Claude：**别建新 README，改我们已有的那个就行**。在这种较长的计划里，很容易就让 Claude 一路跑下去，但有时候你需要叫停、按自己的意思引导它。

仪表盘建好后，我们开一个新的终端窗口来**启动服务器**。在左边这个终端里，我用 `streamlit run` 加要展示的那个 Python 文件 `dashboard.py` 来启动。结果发现我没有 `streamlit` 命令——为了让一切跑起来，我得装这些依赖。那就装：跑 `pip install`、装齐所有必要依赖，确保服务器加载时不会因为依赖出问题。装好后再用 `streamlit run` 跑服务器，就照它提示的那样，输入 `streamlit run` 加我们的 Python 文件名。

## 再迭代：默认年份与月份筛选

回到浏览器看看样子：有营收、有增长。往下滚，我们肯定得核对这些数字是否符合预期，而且能看到还**缺了点东西**。这个仪表盘是个不错的起点，但能看出缺了几样：这些卡片是**空的**、而且其实是多余的，因为我们要的信息已经有了。同时，**从 2024 开始**有点别扭，因为逐年看不到太多信息。所以也许该让 Claude 不仅清理这些地方，还把**默认年份设成 2023**，这样能有稍好看些的可视化；同时确保**能按月份筛选**。之所以想从 2023 开始，是因为 2024 并非每个月都有数据，导致看月度增长时有点令人困惑——那部分数据我们还没有。

那就去提这些要求，丢回给 Claude：「这是个不错的开端，但我想做以下改动。」新起一行，先确保**默认年份是 2023**；接着让 Claude 加上**按月筛选**；最后**去掉每行那张空卡片**。于是它为这些任务更新仪表盘代码：把默认年份设为 2023——不错；加上按月筛选；再更新营收图表，处理「按某个具体月份筛选」的情况。能看到 CSS 也在变，这个图表容器应该会比之前更干净。

回浏览器看效果：2023 成了默认值，好的开始；那些空卡片也没了，很棒。我们就先到这儿，但你可以想象，**只要不断提示下去，就能做出更强大的可视化**。短短时间里，我们从一个又乱又难读难懂的 notebook，迁移到了一个**能部署、能和团队共享、能快速迭代**的仪表盘。
