# 环境搭建与代码库理解

我们要做的第一个例子，是一个端到端的 RAG 聊天机器人。先用 Claude Code 来摸清这个代码库。

在让 Claude Code 帮我们狂写代码之前，先聊聊怎么用这个工具，**快速搞懂一个更大的代码库**。

## 先看看这个应用本身

这里有个应用，我可以就 DeepLearning.AI 的课程资料和 Claude 聊天。我们试着问一门课的大纲，比如：「MCP: Build Rich-Context AI Apps with Anthropic 这门课的大纲是什么？」可以看到，它返回了相当详细的内容，列出了每节课和对应的描述。

带着这个印象，我们来看看怎么快速搞懂**支撑这个应用的底层代码**。

## 用 Claude Code「聊」懂代码库

回到 VS Code，我这儿开着终端，输入 `claude` 回车，就进了 Claude Code。

进来后，我就能开始「和我的代码库对话」了。我先问一个高层次的问题，让它给我一个代码库的总览。

接下来你会看到 Claude Code 做的事：它会以 agent 的方式在代码库里**自主搜索**，找出几个最重要的文件，再告诉我这个应用里到底在发生什么。它不会一个文件一个文件地翻，而是自主地搜索、定位出最相关的那些。

于是我们拿到了架构、关键组件、部分功能的信息。要是有哪块我想深入，随时都能往下挖。

我也可以问更高层的问题，比如「这些文档是怎么被处理的？」这个应用用的是 **RAG（检索增强生成）** 来获取课程信息。想了解这个流程的更多细节，问一句就行。

我们常说：Claude Code 是个很棒的、能和你并肩干活的工程师，但它**更是个一流的「讲解员」**。所以当你在熟悉新代码库、新数据集时，**先把 Claude Code 当成讲解工具**——这样等你真要它写代码时，你心里对整件事的来龙去脉会清楚得多。

这里我们能看到代码库里负责这些事的具体来源：把文本切成块、补上课程上下文、存储课程元数据。这种「快速搞懂一个代码库」的能力，在你对底层技术或语言不熟的时候尤其值钱。你不用挨个进文件夹去琢磨发生了什么，而是可以问更具体的问题，甚至让它给你画图、做可视化。

## 让它追踪一次完整的请求流程

我先让 Claude 做一件事：**追踪一次用户查询从前端到后端的完整处理过程**。

想象一下，你可能只熟悉技术栈里的某一部分，或者根本不清楚这一切是怎么串起来的。Claude Code 这时就能给出很有用的信息。

看 Claude Code 干活时，有个很贴心的点：它会给你一张**待办清单**，让你能跟上它的思路。任何时候你都可以按 `Esc`，把它引导到另一套待办上去；不过这次我对它在做的事挺满意。它会从前端开始追，顺着 API 端点往下，分析我们的 RAG 系统，再搞清楚响应到底是怎么生成的。它读取负责这些任务的相关文件，最后收尾，给我们一份有力的总结。

在这个环境里，你可以一直待在 VS Code 里，也可以单独开一个专门的终端实例跑 Claude Code——完全看你习惯。

它做完后，我们能看到一条非常详细的处理路径。我不仅能一步步读，还能让 Claude 把它写进一个文件。我能很细致地看到：前端用 JavaScript 在做什么、到了后端发生了什么、RAG 系统在做什么、响应是怎么生成的，最后是怎么在向量数据库里检索、怎么过滤出需要的东西、拿到结果、再发回给用户的。

这个应用里发生的事可不少，而我可以用 Claude 去深挖其中任何一块。

## 让它画张图

假设我是那种「看图最容易懂」的人。那就让 Claude 画一张图，把这个流程画出来。

我们可以让 Claude 画网页可视化的图，也可以要 ASCII 字符画。但这次我们看看 Claude 凭它自己的智能、对应用的理解，会给出什么。

结果出来了：一张很漂亮的图，一步步展示了整个流程。它能画出这种示意图。要是想要网页应用那种效果，我们也可以让它用 D3.js 或 recharts。但就眼前这张图，已经很清楚了：前端向后端发请求、调用必要的函数、在涉及历史记录时生成相应的响应、带着系统提示词和工具、查询直接和大语言模型对话、决定下一步去哪、用 Chroma DB 在向量数据库里检索、拿回结果、格式化、再发给模型产出最终回答。

这里头细节相当多。需要的话，我们甚至能给 Claude 加上额外的工具来生成想要的可视化。但开箱即用、就这么快速高效地拿到这些信息，已经能让我们用过去**零头的时间**就搞懂这个代码库。

## 「我怎么把它跑起来？」

带着这个思路，我们问个特别简单的问题：「我怎么运行这个应用？」你可能正面对一项新技术、一个新想法，这时候很朴素地知道「怎么把它跑起来」就很舒服。我能看到 API 文档、Web 界面，以及我需要的环境变量——齐活，可以开干了。

## 关键一步：`/init` 与 CLAUDE.md

知道了怎么开始和 Claude Code 对话，我们来聊聊它一些更强的功能。

当你开始在 Claude Code 里处理一个应用时，我们建议你做的头几件事之一，就是运行 `/init` 命令。在 Claude Code 里敲下斜杠，你会看到一长串可用的内置命令。`/init` 能帮我初始化一个带着代码库文档的 `CLAUDE.md` 文件。

`CLAUDE.md` 对于给 Claude Code 引入「记忆」是**至关重要**的——它让 Claude 知道在你的代码库里怎么干活最合适。这个文件很适合用来指定你希望东西「怎么跑」：比如怎么跑测试、怎么做代码检查（linting），以及任何你希望 Claude 每次处理这个项目时都长期记住的事情。

`/init` 不用你从零写起——它会分析代码库，从高层次搞清楚「每次处理这个应用时它都该知道些什么」。

### 三种 CLAUDE.md

你可以建三种 `CLAUDE.md`：

1. **项目级**（就是 `/init` 生成的那种）：放在你的应用里，可以在嵌套子文件夹里放好几个。它会和其他工程师共享，并**提交进版本控制**。
2. **本地级**（`CLAUDE.local.md`）：放你个人的指令和定制——比如专属于你编辑器、终端环境的设置。它被 **git 忽略**，不和别人共享。
3. **用户级**：放在你主目录下的 `.claude` 文件夹里。可以把它当作你这台机器上**所有项目通用**的全局 `CLAUDE.md`。如果你希望 Claude 在你用它构建的一大批项目里都遵守某些指令，这个就很有用。

我们让 Claude Code 去翻不同的文件，好让它知道怎么把这份 `CLAUDE.md` 写得最合适。这份文件是要加进你当前 git 项目、和团队成员共享的。随着越来越多人参与，大家都能往里补充；需要的话，你还能在子目录里嵌套 `CLAUDE.md`，给后端、前端或文档这些地方更具体的指令。

在 VS Code 里配合 Claude Code 用，有个很爽的地方：文件一有改动，我就能在编辑器里**直观看到**。而且每次 Claude Code 要用某个工具，它都会**向我请求权限**。这种「人在回路」（human in the loop）在你刚上手时特别重要。如果你不需要它每次都问，也可以选第二个选项——直接自动接受这些改动。然后我们就会看到，一份 `CLAUDE.md` 已经生成好了。

快速过一下：它给了我们项目概览、关键技术、架构总览，还有一张小图、一些核心组件等等。想改这份 `CLAUDE.md`，随时都行。它继续搜代码库的过程中，还会接着往我的 `CLAUDE.md` 里补内容，并给我一份「做了什么」的总结。

## `/ide` 与编辑记忆

在 VS Code 里用 Claude Code，我能指定「我正在哪个文件里」，甚至能拿到具体某些行的信息。要打通这个，我用 `/ide` 命令——可以看到，我已经和 Visual Studio Code 连上了。

连上之后，我一打开某个文件，它就会被标记出来。这样 Claude Code 就拿到了「我在哪个文件」的正确上下文；我对这个文件有疑问时，它也更容易对上号。

想往 `CLAUDE.md` 里加规则，有两个顺手的办法：

- **直接用自然语言让 Claude 改**：比如说一句「把『永远用 UV 跑服务器，别用 pip』这条加进项目的 `CLAUDE.md`」，Claude 就会帮你写进去。（UV 是 Python 生态里的一个包管理器，我想确保 Claude 别搞混。）
- **用 `/memory` 命令**：它会列出当前生效的所有记忆文件——进 git、全队共用的**项目记忆**；被 git 忽略、只对你有用的**本地记忆**；以及适用于你所有项目的**用户记忆**——你选一个，就在编辑器里打开来改。

> 与课程录像的差异：课程里讲师用的是 `# 内容` 这个快捷方式来快速写记忆；该快捷方式在新版 Claude Code（v2.0.70 起）已被移除，上面两种是当前的等价做法。

改完一看 `CLAUDE.md`，里面就有了关于用 UV 的说明。想更具体，我还能再加一句：「确保用 UV 管理所有依赖。」凡是提到依赖的地方，现在都带上 UV 了。

## 几个常用命令：`/help`、`/clear`、`/compact`、`/memory`、`Esc`

前面聊到了 `/init` 这样的内置命令，这里再展示几个有用的（后面课程里我们甚至会自己造命令）。

- **`/help`**：一上来就给我所有命令的简短说明和摘要。刚熟悉 Claude Code 时很好用。
- **`/clear`**：清空对话历史、从头开始（但保留项目记忆）。当你切换方向、要做新功能时特别有用。
- **`/compact`**：如果你想接着聊、想要更小的上下文窗口、但又想保留一份「之前做了什么」的总结，就用它。它清掉历史、但留下摘要。
- **`/memory`**：列出并打开当前生效的记忆文件来编辑。注意它只是「打开文件」，在命令后面直接写规则是没用的。
- **`Esc` 键**：让你从当前正在跑的命令里跳出来。比如解释代码库中途想停，`Esc` 能打断它再继续往下走。拿不到你要的东西，随时打断。

## 收尾：让 Claude Code 帮你 commit

下课前，再说一个很有用的点：Claude Code **会用 Git**。

我对这个应用做了点小改动，想把它们 add 并 commit。我不用自己手敲 Git 命令、再绞尽脑汁写提交信息，而是让 Claude Code 来干。它能帮我 add、commit 必要的内容；更妙的是，它写出来的**提交信息非常清楚、有描述性**。

这一点在两个时候极其有用：之后让 Claude Code 帮我们追溯 git 历史改动时，以及把代码推到 GitHub、别人来看我们改了什么时。所以我们 add、commit。
