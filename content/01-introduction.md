欢迎来到《Claude Code：高度自主的编程助手》这门短课。它由 DeepLearning.AI 和 Anthropic 联手打造，又一次请来了 Anthropic 的 Elie Schoppik，来跟我们分享用好 Claude Code 的最佳实践。

我（吴恩达）特别期待这门课。Claude Code 是我现在最喜欢的编程助手——它把我和很多开发者的效率提升了一大截，而且是个很有深度、值得细细琢磨的工具。所以我想和 Anthropic 一起，把背后那些最重要的思路，系统、完整地讲清楚，争取做成这方面最权威的一门课。

## AI 编程这几年，变化有多快

过去这两年，AI 辅助编程发展得非常快。一开始，大家只是偶尔问问大模型一些编程问题；后来有了 GitHub 的自动补全；再后来，各种工具变得越来越「自主」。

Claude Code 发布的时候，在「自主程度」上明显又上了一个台阶——也就是说，这个助手能自己独立完成的事情更多了。很多人都没想到：你可以丢给它一个任务，它能埋头干上好几分钟，有时候甚至更久。

到了今天，已经有开发者不只是指挥一个 Claude，而是同时调度好几个，让它们并行处理代码库的不同部分。但要协调好这一切，背后是有最佳实践的——而这些经验目前还没被广泛知晓。如果你身边没有特别懂行的人带，那么把这些最佳实践真正吃透、搞清楚它们是怎么带来那种惊人效率的，你还有很大的提升空间。

## 用好 Claude Code 的关键：给清晰的上下文

聊到这些最佳实践，有一条特别关键：**给 Claude Code 提供清晰的上下文**，帮它高效地完成你想要的任务。具体来说就是：

- 把相关的文件指给它看；
- 清楚地描述你想要的功能和效果；
- 用 MCP 服务器以及生态里的其他工具，把 Claude Code 的能力恰当地扩展开。

## 这门课会带你做三个项目

课程里，你会把这些最佳实践用在三个不同的例子上。

**第一个：RAG 聊天机器人。** 你会从前端到后端把功能实现出来，包括重构代码、写测试，再用 GitHub 集成来处理拉取请求（pull request）和修复 issue。这过程中你会用到 Claude Code 的很多功能，比如规划、思考模式（thinking mode）、开多个并行会话，以及管理 Claude 的记忆。

**第二个：Jupyter notebook 玩转电商数据。** 我们会换个方向，用 Claude Code 重构 notebook、删掉冗余代码，再做出强大的仪表盘和 Web 应用。

**第三个：从 Figma 设计稿到前端应用。** 最后，我们会基于一个 Figma 上的视觉设计稿，配合 Claude Code、Figma 的 MCP 服务器和另一个 MCP 服务器，把设计导进来，然后以 agent 的方式自主地迭代、测试、构建出一个强大的前端应用。

## 剧透一下：Claude Code 的架构有多简单

下一节，Elie 会讲 Claude Code 底层的架构——你可能会惊讶于它居然这么简单。

Claude Code 只依赖少数几个工具：在你的代码文件里搜模式、列出目录、查看文件、跑正则。它**不会**把你的代码做语义嵌入，也不会转成什么可检索的特殊结构。让 Claude Code 这么好用的一大原因，恰恰在于它能像 agent 一样自己读代码、在 `CLAUDE.md` 这样的文件里记笔记，自主搞清楚你的代码库里到底在发生什么，再据此决定下一步怎么推进。

正因为它不需要给代码库建索引，你的代码可以一直留在本地——关于这一点带来的安全影响，我们后面会专门聊。
