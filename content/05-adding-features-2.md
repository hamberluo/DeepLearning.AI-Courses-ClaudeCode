# 添加功能（下）

接上一节，我们让 Claude Code 用 Playwright MCP 服务器去摸索、搭出需要的内容。

## 让 Claude 自己截图、自己改、自己验证

我让 Claude Code 用 Playwright：访问我们当前的页面、看看那个「新建对话」按钮。我的要求是——让这个按钮和下面 Courses、Try Asking 那些链接长得一样：**左对齐、去掉边框**。

动手前，它会就这些工具向我请求许可。它会访问那个页面、截图、然后做该做的事。我们认可，并选择「以后用这个工具不必每次都问」。

可以看到，浏览器**用程序自动开了一个新标签页**，跳到我们的页面去截图。让 Claude Code 拿到截图、分析它看到的东西——它一眼就看出了问题所在。**这样我们就不用手动截图了，它能用程序自我修正。**

因为我这次没开自动接受，所以能在 VS Code 里看到正在做的改动。一改完，新效果里边框和背景都没了，我觉得不错。那就应用这些改动、继续往下改。左对齐看着挺好。它会**再截一张图**，验证自己改完的样子对不对、图标前缀用对了没、和其他区块是否一致。

回浏览器看看。刷新页面，挺好——不过这儿多了个 `+`。那就让它去掉。它已经左对齐、也用了我们之前喜欢的图标。我说：「现在有两个加号图标，把更靠近文字的那个 `+ New Chat` 去掉。」它发现 HTML 内容里本来就有一个加号，于是把多余那个删掉。

需要的话它会再截一张快照。可以看到，Claude Code 发现没有打开的标签页，就**自我修正**，重新打开、截了所需的图。再看效果——好多了。

可以想象，用 MCP Playwright 这类工具来搭复杂界面，让**构建、设计、测试**都变得轻而易举。

## 转战后端：再加一个工具

前端改得挺漂亮了。现在去后端。和之前一样，我们**从头开始**——不在这段对话上接着干，而是开一段新的。`/clear` 清空历史，重新来。

这次我们要在后端加功能。先写提示词、说清要做什么：我想**再加一个工具**，能访问某一门具体课程，并对每门课列出**课时编号、课时标题和描述**。因为现在我查看一门课时，拿到的数据还比较笼统。

我们要让 Claude Code 改的是 `search_tools.py` 文件。看一眼这个文件：目前里头只有**一个工具**，用来搜索内容、获取某门课的详情。我们要加的**第二个工具**，会让我们能拿到每门课里各个课时的更详细信息。

照旧，**先出计划**，确认计划没问题，再开始改具体文件。Claude Code 能看到当前架构、知道该怎么实现这个大纲工具；而且因为我们之前有了 `CLAUDE.md`，它能更快理解要做什么。

我们看看要实现什么、确认是在对的文件里做对的事：建好这个工具后，**更新系统提示词**确保能拿到那份额外数据，再把工具**注册进 RAG 系统**。和往常一样，有想改、想建议的现在就提。

那就让 Claude Code 干活。如果一切如预期，我们应该能就一门课提问、拿到课时层面更详细的信息。可以看到，它不只在改底层 Python 代码，还改了系统提示词，并在这里注册了我们新建的工具。

待办清单跑完，回浏览器看看实现得对不对。它给了一份漂亮的总结，而且我们随时都能再改。

回到浏览器，试着问某门课的信息。如果没问题，我们应该能拿到更详细的内容，包括这门课的链接。这里能看到各个课时的名字；想的话，我们甚至能再做点功能，给每个课时都配上来源。

下一节，我们会聊聊**出问题时怎么办**——怎么用 Claude Code 调试、写测试，让我们对「和 Claude Code 一起写出来的软件」更有信心。
