# 基于 Figma 设计稿创建 Web 应用

这最后一节，你会把 Claude 连上 **Figma 的 MCP 服务器**，把一张设计稿导入 Claude Code，并把应用开发出来。我们来玩点有意思的。

## 这一节要做什么

我们已经看过怎么用 Claude Code 快速搞懂代码库、创建应用、跨多种环境工作。现在我想展示 Claude Code 一个非常强大的能力：**配合 MCP 服务器，把 Figma 这类工具里的设计稿，快速变成 Web 应用**。

为此我们要用到 **Figma 的 MCP 服务器**——你需要一个 Figma 账号。（如果你不想为了 Figma 的 dev mode 而订阅，我们也会给一个替代方案。）我们还会用 **Playwright 的 MCP 服务器**，这样就能：分析 Figma 的设计稿、生成所需的 HTML，再通过在浏览器里打开它、截图，**用程序去测试**怎么和这个应用交互最合适。

因为我要用更现代的技术栈做前端，所以我会用 **Next.js**。我先在当前文件夹里用最新版本创建一个 Next.js 应用，大多沿用默认项，让它装好必要依赖。

> 没用过 Next.js 完全没关系：敲几条命令行命令，转眼就能在浏览器里看到了。

## 准备 Figma 设计稿与两个 MCP 服务器

趁它装着，我们去看看 Figma 里的设计稿。我在 Figma 里有一张设计稿，想用它做一个基于**美联储经济数据（FRED）**的仪表盘。这张稿在图层和背后的分析上**并不算特别详细**，但足够让我起步了。

在 Figma 里，我先去**偏好设置（preferences）**，勾选 **enable dev mode MCP server**。勾好后，把我这张设计稿对应的**图层复制下来**——待会儿指定要让 MCP 服务器用什么时会用到。

Next.js 应用建好后，我们要给 Claude 加上想用的两个 MCP 服务器：Figma 和 Playwright。先加 Figma 的 MCP 服务器命令，再用同样的方式加 Playwright 的（本地启动）。

> 注意：尽管我们之前已经加过 Playwright，但**这是另一个项目、另一个环境**，配置不会自动套用到我每一个 Claude Code 应用上。**每个项目都得各加一次**。

确认配好没：进 Claude，用 `/mcp` 命令看看。一看，两个都连上了。再看 dev mode MCP 服务器，能看到它给了**五个工具**：取底层代码、取图片、取我 Figma 里某张设计稿的设计规则等等。

## 让 Claude 读稿、生成代码、再用 Playwright 验证

两个 MCP 服务器都连上后，让 Claude：用下面这张 Figma 设计稿、配合 Figma MCP 服务器去**分析并构建所需的底层代码**；让它用 **recharts** 库来画图表；然后用 Playwright MCP 服务器**看看应用长什么样**。

动手前我先做个小调整：如果你能切、而且不在 Pro 套餐上，可以换用 **Opus** 模型；不行的话 Sonnet 也能干得不错，但**任务偏复杂时 Opus 会稍好一点**。切到该模型后，跑提示词、看它表现。

它先连上 MCP 服务器，确保用对设计稿和工具去读驱动这张稿的底层代码。可以看到它用 Figma dev MCP 服务器的 **Get image** 工具，接着用 **Get Code** 工具拿到设计稿背后的代码。然后用 npm（或包管理器）装必要依赖——这里显示没装，所以 Claude Code 多半会让我们装。我们照做，继续。

因为是在这个 Next.js 应用里，大部分工作会在 `app` 文件夹中进行。它会分析全局 CSS，开始创建主仪表盘结构，加一点元数据——看着不错，所以后续编辑我直接让 Claude 自己跑。接着创建仪表盘布局，用 React 里**基于组件**的架构来搭。

底层结构建好后，开始确认效果。因为我已经把服务器跑起来了，就告诉它「**别启动服务器，它已经在跑了，继续**」。然后用 Playwright 来测：导航到 `localhost:3000`、截张图。在 Playwright 里能看到，跟设计稿比，目前已经相当不错了——有些柱状条上多了点样式，但相比我们最初那张稿，这是个很好的开端。说实话，我觉得这看起来还更漂亮些。

我们还会看到一些改动正在进行：侧边栏的布局要调，而且随时能让 Claude 在这张稿上来回迭代。

> 有一点很重要：这张 Figma 稿的图层和底层组件**并不多**，所以效果在很大程度上取决于**你那张设计稿的质量**。但就这么点时间，已经是个很好的起点了。

能看到搭出来的东西和稿子高度吻合。稍加打磨、再借 MCP 服务器验证可视化、在稿子基础上往下做——**原本从零搭可能要好几天的东西，几分钟就能搞定。**

## 接上真实数据：调用 FRED API

你可能会想：接下来呢？这张稿只是个起点。而且**这些数据其实有 API 可取**。所以我可以让 Claude Code：**用美联储经济数据（FRED）的真实数据来填充这些图表**。

我们让 Claude Code 用它的一个**网页搜索**工具去找信息、改成真实数据。这里会看 CPI、失业率、收益率等等。当然，你也可以想象这是从某个后端拉来的数据。但这里我们要展示 Claude 的研究能力：怎么读懂 API 文档、怎么取数据。这过程中可能需要一个 **API key**。所以一边研究，Claude 会一边告诉我们需要准备什么。

（那张稿的导航栏里还有几样东西只是用来做视觉展示的，但之后我们想加什么底层功能都行。）

研究完，它意识到：要从美联储取真实数据，我得填一个 **API key**。我去自己的账号申请一个——流程相当简单。拿到 key 后，它就开始替我写额外的代码来取数据、把数据可视化地展示出来。我把 API key 更新进去。

更新好 key，看看 Claude 进度如何。它现在写了一个**取经济数据的服务**，接着更新仪表盘、用我们的 API 取真实数据。

用 Playwright 测一下，再到浏览器里看看视觉效果，看有没有底层代码需要改得更好看。

**只用一点点提示，我们就从「带假数据的设计稿」走到了「真正接入真实数据源」。** 做完回到 `localhost:3000`，会看到我们取的数据不再是虚构的，而是真实的失业率、十年期国债收益率等等。我们在这里做了不少工作来**代理（proxy）请求**，还加了不少交互功能。

去看看效果：从最初那张「带假数据、功能不多」的稿，短时间里就变成了相当强大的东西。这里加载的数据真实反映现实世界的信息。再想象往里加更多功能——可以按 tab 切着看会是什么样。但你看，只需一点点工作：用 MCP 服务器从真实环境拉数据、用 Figma 稿生成 UI，你就能体会到**前端开发能有多快**，尤其是搭建强大的真实界面时。

你可能想**验证这些数据确实来自数据源**，我们也用这个详尽的功能做到了：能轻松看到数据来自哪里、长什么样，并把它追溯回我们正在搭的仪表盘。

这里只展示了几个关键指标。也许下一步我想搭自己的界面，或者用另一张 Figma 稿做通胀、就业等等。我们就从这块数据起步——但我很想看看，**用这个界面、用你指尖这些数据，你还能搭出些什么。**
